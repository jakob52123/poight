# 招式动画接入指南（V1-core）

> VH 后续接入：默认额外启用皮卡丘/喷火龙八招的独立视觉层，详见 [主角八招接入.md](主角八招接入.md)。以下三样板章节是 V1-core 基线说明；其物理、像素及通用星门槛不变。`?anim=old` 同时关闭 VH 新外观。

## 范围与总原则

默认只替换 watergun / icebeam / earthquake，加所有实际直接命中的 impact 星，以及所有 nova 的棕黄色虚线圆环预警（不改判定）；`?anim=old` 恢复 M4 路径（仍包含独立合入的 B1）。主角八招及其他招式的发射/攻击外观不动。数据中的伤害、冷却、体力、射程、speed、判定形状均不变。

`招式动画引擎.js` 保留 V1p ESM 原文件，构建通过 `招式动画/打包.py:runtime()` 包装闭包，导出 `window.PoightAnimationEngine`。`招式动画接入.js` 是游戏安全边界，**不要直接把 Showdown 的 contactattack 坐标写回角色**。

## 素材流程

1. 先读 ref-moves 的 `对照表.tsv`、`卡片/<id>.png`、`pokeemerald/data/battle_anim_scripts.s` 对应 `Move_...` 段。
2. 从 `色板映射.tsv` 的 ANIM_TAG 找 PNG 与 palette；优先复制 `还原贴图/` 已还原图片，不把灰度索引图当成最终配色。保留来源和哈希。当前副本在 `原版/`，透明索引已经处理。
3. `招式动画.json.moves[id]` 提供 Showdown 事件/时间/候选 impact；原始数字是横版回合制时间，不等于实时战斗判伤时刻。`特效映射.json` 是贴图/帧框；`打包.py` 将文件变成带 hash 的本地 assets URL，JSON 直接内嵌 HTML，不 fetch。
4. 新贴图只新增文件，严禁覆盖保护图集。将 sprite key 加进 `打包.py:sources`，写正确裁切框。打包清单含所有实际使用的图像、声明、许可证、源码；file:// 可直接离线加载。

## shot / fan（水枪）

M4/R3 把 watergun 的游戏 kind 登记为 beam，但底层仍是飞行弹体。为遵守“不改判定形状/参数”，这里保留其 kind、原物理路径和射程预算，只把 **视觉路由** 改为 shot 水珠列；不要为分类名修改 MOVES。

- `PoightMoveAnimations.uses(id)` 是唯一新表现白名单。
- `生图招式.emit` 仍调用旧 `releaseOrigin` 并创建原物理弹体。`prepare(b, api)` 只新增 coreShot、originAnchor、visualOffset，不改变 x/y、ux/uy、speed、range、radius。
- `anchor()` 用已有逐角色/逐方向/逐帧的 r3-mouth（M4 已合并的嘴部锚点），缺少则 mouth；通过原 T5 `heroAnchor` 坐标变换，包含角色缩放、动画帧、空中高度。
- `bullet()` / `path()` 只画外观；水枪由 **6 颗**原版 SMALL_BUBBLES 水珠首尾相接构成，从嘴锚点至物理前沿沿局部法向弧线连续喷出，八个方向都保留弧线。每颗直径取 `max(14, .30*height, length/5+2)`；用高饱和蓝色阶和少量白色高光，不用透明淡紫泡。fan 为每个原弹体单独套外观，不新增伤害次数。
- 打包时只对原版副本作内存重着色：水珠/水花用蓝色阶，冰晶用青色阶，尘土用深棕色阶；`原版/` 与原色板映射文件原字节保留。命中画放大的 WATER_IMPACT、水滴迸散和通用星。
- 物理 `bodies.segment` 接触仍优先比较墙体阻挡。在接触分支调用 `projectileContact` 留下短暂可见终点，然后 `damage(..., point)`；命中水花和通用星由成功 damage 触发。未命中、被墙拦截、闪避或免疫不能伪造掉血。

## beam（冰冻光束）

- 同一个物理弹体作为光束头，不改为 instant ray，不额外结算每颗冰晶。
- `path()` 从仍在施放的实时嘴部锚点（施放结束后冻结发射锚点）连接至物理前沿；连续冰蓝贴图/光晕条上平铺原版 ICE_CRYSTALS，末端不超过物理头。图案密度、色光、横向微扰可以改，但不能让光束先贯穿目标再判伤。
- 宽度通过 `readable(height).beam=max(10,.25*height)` 计算；连续亮白芯、饱和青色外晕，冰晶 22–28px（至少旧版两倍）。外晕/冰晶不能取代连续不透明主体宽度。
- 在碰撞那一 tick 保存最终 ribbon，防止子弹 splice 后整条光束立即消失；尾迹 0.1 秒内淡出，命中冰晶迸散 0.26 秒内结束。成功命中把目标加入 `frost` 计时表，`对战.js:spriteDraw` 复用当前角色帧的 alpha 轮廓绘制青白结霜边，0.3 秒模拟时间后清除；不是矩形白框，不修改精灵图集。

## nova / zone（地震）

- `瞄准预警.js` 对**全部 nova**使用施放者中心的 `ground-ring`：棕黄填充 alpha=.14、棕黄边缘 `[7,5]` 虚线，最后 .1 秒也不变白。地震预警半径是原方格角点外包半径 `hypot(72,72)`；只是提示，不参与判伤。`?anim=old` 保留原 grid 预警。
- 地震仍用 M4 的 `bodies.rect(target, x-72, y-72,144,144)` 与 clearLine；**不能偷偷改成 circle**。
- `nova()` 创建 core-nova；`stepNova()` 按相同半径函数推进波前，目标距离穿过半径那一 tick 才调用 damage。攻击 group 保证不重复伤害。当前波前 .45 秒扩散，.6 秒内完全清除。末端半径由原方形和目标八方向碰撞半径的最大外包范围确定，不扩大合法命中集合。
- 半径和视觉 `drawNova()` 共享 e.radius，圆形波前必须在世界坐标画，不能压成椭圆后仍按圆判伤。区域外不判伤，即使残余尘土经过。
- 后续 zone 可以读取源动画事件，但必须显式指定经过人工审核的 impact；从弹道实际落点创建动画，使用 visible-front 或落地事件触发原有伤害函数。局部背景半径约三身长、总恢复不超过 .6 秒。不要启用未审阅的 113 招自动 impact 候选。

## melee / spin / rush（留给后续批次）

- 现有 B1 和 R1–R3 路径保持不变，本批不批量替换。
- 可以 `engine.cast(id, attacker, defender, {windupMs, onImpact})`，在模拟时钟 update 驱动一次 impact；判定通过时再调用原 damage，draw/seek 绝不能结算伤害。
- 原 contactattack 的整身移位只可通过 `boundedPose(instance, role, ms)` 取得视觉 offset：上限半个 actor.height，impact 后 120ms 必定回零；只在 spriteDraw 的 save/translate/restore 里应用，不改碰撞位置。动画取消同时 cancel 实例。回调接触仍要通过原射程、朝向、墙体、空中、无敌门禁。

## 通用命中与时钟

`对战.js:damage` 是统一入口。在 `feel.hit` 同一调用栈内调用 `animations.impact`；尺寸为 target.visibleSize[1] × **max(0.8, 0.6+0.4×最终伤害/35)**。damage>=25 或 mult>=2 加白色放射冲击线。纯 DOT/反伤/治疗不伪造接触；属性免疫和完全格挡没有成功直接伤害。

动画使用战斗模拟 dt，顿帧时视觉与角色/弹体一起冻结。所有 sprite 绘制只读模拟；reset 清除 burst/ribbon/engine 实例。测试 snapshot 的 animation.releases/contacts/bursts/ribbons 只作审计，不参与判定。

## 可读尺寸硬规则（所有后续批次必须遵守）

1. 飞行弹/水珠/弹体：**实际不透明主体**直径 ≥ 施放者 `char.body.visibleSize[1]` × **30%**，且 ≥ **14 世界像素**。不能拿透明画布框、外晕或 CSS 放大倍数凑数。
2. 光束：实际不透明主体宽度 ≥ 身高 × **25%**，且 ≥ **10 世界像素**；必须有中心亮度 ≥ **230** 的亮芯和属性色外晕。宽度按光束法向测，不能用斜向包围盒或单个最大冰晶蒙混。
3. 主色用高饱和属性色，HSV **S ≥ .55**。水用 `#3c8cff` 一系的深浅蓝，冰用 `#9fe8ff` 一系的高饱和青色外晕 + 青白亮芯；显式白芯/白色高光不计入属性主色饱和度（仍要求属性色覆盖足够面积）。在正规场-A 红土、自然场-A 草地上，主体与同位置背景平均亮度差均 ≥ **60**。原版色板过淡可按属性重着色，但保留原版轮廓与素材来源。
4. 命中星按上式随最终伤害放大，**下限 .8×目标身高**；重击白色放射线仍在相同 damage 调用栈触发。

### 像素测量口径（不能仅断言配置值）

`tests/招式动画像素.js` 包装真实 `path/drawNova`，在真实 Canvas 变换下把同一次绘制镜像到透明层；不替换参数、不伪造颜色。取实际 HP 减少前 **1/120 秒**的帧，另在同一时刻只屏蔽该特效重画背景。保存 composite/background/mask 三份 PNG。

- 不透明阈值 alpha≥250；逆 Canvas 变换回世界像素。水珠测真正单颗轮廓法向直径并检查 5–7 颗；光束测中段八个截面的**最小**不透明宽度，并测中心线亮度。
- 饱和度只排除 S≤.12 的显式白芯/白高光，剩余全部主体像素平均 S≥.55，属性色像素占不透明主体 ≥30%。不是先筛选 S≥.55 再自证。
- 平均亮度采用显示像素 Rec.709 加权 `Y=.2126R+.7152G+.0722B`，主体与同位置背景取相同 mask 后比较平均值，差≥60；不是取最亮的一个像素。弹体中段取轴向 25%–75%，避免把角色与 HUD 算进背景。地震取可见波前附近实际不透明裂纹环。
- 两张正式地图各测试三样板一次，不挑第三张低亮背景；8 方向实战另测锚点、接触/掉血同 tick 与截图。尺寸和色彩测试不修改伤害、射程、判定和角色体型。
