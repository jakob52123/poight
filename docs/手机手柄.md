# 手机选人与手机手柄（v2）

## 本地运行

已有完整构建/合法素材时（Python 3.10+，中继不需要第三方包）：

```sh
python3 构建完整版.py
python3 预览服务.py --candidate --host 0.0.0.0 --port 8899
```

电脑也必须打开局域网地址，例如 `http://192.168.1.20:8899/`，不能用 localhost 或 127.0.0.1 生成二维码。电脑选好角色、确定对战后，右上角展开「手机手柄」，点「创建手柄房间」。手机和电脑接入同一 Wi-Fi，扫描二维码，或者访问 `/手机手柄.html` 输入六位房间码。手机横屏使用摇杆、四个招式、跳跃、闪避；「开始 / 继续」通过原游戏 start API 继续。角色/地图/配招仍在电脑端选择。

**源码快照仍有 README 所列构建阻塞，不是补齐素材后的可复现构建。** 本次本地验收使用下载的在线页面嵌入数据与素材（不提交），再覆盖源码 CSS、手机输入类和战斗代码：

```sh
# local-live.html 为自行下载的在线页面；assets 为它引用的合法本地测试素材。
# 下载前把它们加入 .git/info/exclude，绝不能提交。
python3 tools/local_live_fixture.py
python3 预览服务.py --host 0.0.0.0 --port 8899
```

此辅助工具不是正式构建器。默认同时覆盖源码选人 HTML；`--live-markup` 保留在线版额外的 AI 页脚。`--before` 使用修复前的 6a9ccf5 CSS，便于与相同 HTML/数据比较。仅用于诊断版本间布局差异。

## 选人修复与复现范围

旧 CSS 给全屏 `100dvh` 弹窗固定的 44/56px 页脚轨道，又叠加旧窄屏 block/flex、85px 高度、不可收缩/不换行的操作按钮；弹窗裁切溢出，滚动的是角色列表而不是页脚。在线版额外 AI 控件的 HTML + 快照 CSS 可稳定复现：390×844 时确定按钮 y=846（屏高844），844×390 时按钮右边缘938（屏宽844）。纯快照选人 HTML 在本机 Chromium 上没有稳定重现同样的缺失；在线版当前完整 CSS 也已有其他页脚适配。因此截图明确是**在线数据/HTML + 旧快照 CSS 的本地回归夹具**，不宣称当前线上版本本身必现。

修复在 `选人页.css` 约束页脚为单列 grid、隐藏非操作摘要、按钮四列可收缩换行，并固定页脚轨道中的 sticky 底栏，尊重现有 safe-area 外边距。未改动角色提交逻辑；真实触摸确定后，回归断言战斗角色为皮卡丘对妙蛙种子，而非只检查预览头像。分别验过源码选人 HTML 和在线选人 HTML。

## 架构

- `预览服务.py` 在同一个 HTTP 端口提供静态控制页和 `/relay` WebSocket upgrade；`手机手柄中继.py` 是 Python 标准库有界文本帧中继，不参与游戏模拟。
- 电脑创建随机六位房间；每房间一个电脑、一个手机。房间码即临时控制权，不要公开传播。主机与手机各有不可预测的恢复 token，重连可替换自己的半开连接；第二部无 token 手机被拒绝。双方离线五分钟后，下一次请求清理房间。进程重启失效。
- `手机手柄.js` 通过 `PoightMobile.remoteInput()` 送入统一输入层；`moveVector()` 合并远程方向，键盘优先；跳跃/闪避/招式/开始仍调用战斗现有 API。选人/其他 dialog 打开或演示模式时拒绝远程输入。
- 摇杆事件即时发送，另以 20Hz 刷新保持态；700ms 无方向更新自动归零。失焦、触摸取消、断线也归零；不重复回放招式。
- 连接状态显示在两端；400ms 起、最多8秒的指数退避带抖动；应用心跳与25秒无回应检测应对半开网络。断网期间游戏仍在电脑运行，不自动暂停。
- QR 使用本地 vendored `qrcode-generator` 1.4.4（Kazuhiko Arase，MIT，`vendor/qrcode-LICENSE`），无运行时 CDN。
- 安全边界：同源 Origin 校验、必须 masked/FIN 文本帧、最大2KiB、输入向量/动作/序号校验、每连接100帧/秒、最多100房间、有界异步发送队列，慢读者不持有全局房间锁。没有用户登录或互联网级 DoS 防护；推荐私有/LAN 使用，不替代生产网关限流。该小型实现仅面向浏览器文本消息和应用层心跳，不支持分片、二进制、64位长度帧或协议级 ping/pong，不是通用 WebSocket 服务器。

## 部署与限制

需要支持长连接的单进程 Python 主机（房间保存在进程内存；多 worker 需要共享房间/粘性路由）。不能只部署到静态托管。HTTP 与 WS 同源；HTTPS 页面必须经 TLS 反向代理使用 **wss**。代理 `/relay` 到预览服务并转发 `Upgrade`、`Connection`、原 `Host`；保持 Origin 同源，代理空闲超时应大于30秒。例：Nginx `proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; proxy_set_header Host $http_host;`。防火墙开放所选端口；公网环境另加网关连接/请求限流、访问控制、HTTPS 和服务监控，部署修改版须遵循 AGPL 源码提供义务。

目前一部手机控制1P，电脑AI为对手；双手机PvP是后续工作，需要先给现有战斗层增加2P输入归属，不能只把第二手机的数据混进1P。无视频串流、无公网穿透、无跨进程房间共享；浏览器后台/锁屏可能冻结连接，回到前台后会重连。刷新电脑页需新建房间；网络重连不需要重扫。手机可竖屏连接，但横屏布局最佳。尚未进行真机 iOS/Android 或真实 Wi-Fi 丢包压测。
